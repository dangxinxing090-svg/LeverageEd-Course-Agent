## 一、数据库层改进

### 1.1 自动 Fallback 机制

**原设计**: 仅支持 PostgreSQL，需手动配置和启动

**改进后**: 支持 PostgreSQL 与 SQLite 双模式，自动检测和切换

```
启动流程:
1. 读取 DATABASE_URL 环境变量
2. 检测 PostgreSQL 是否可连接
   ├─ 可连接 → 使用 PostgreSQL
   └─ 不可连接 → 自动 fallback 到 SQLite
3. SQLite 启用 WAL 模式，避免 disk I/O 错误
```

**配置方式**:
- 方式一（PostgreSQL）: `DATABASE_URL=postgresql://user:pass@host:port/db`
- 方式二（SQLite，默认）: 不配置或留空，自动使用 `backend/ai_education.db`

**适用场景**:
| 场景 | 推荐数据库 | 说明 |
|------|-----------|------|
| 快速体验/开发测试 | SQLite | 无需安装额外服务，开箱即用 |
| 生产环境 | PostgreSQL | 支持高并发、事务完整性、数据备份 |

### 1.2 数据持久化

**新增表结构**:
| 表名 | 用途 |
|------|------|
| `teaching_sessions` | 教学会话管理 |
| `chat_messages` | 聊天记录存储 |

**初始化命令**:

## 二、知识体系生成流程优化

### 2.1 原流程（V1.0）

```
用户提交主题
    ↓
后端并行调用两个 LLM（asyncio.gather）:
    ├─ 全景介绍 Agent → 输出全景介绍文本
    └─ 知识拆分 Agent → 输出三层知识体系 JSON
    ↓
全部完成后一次性存入内存缓存（knowledge_cache）
    ↓
前端通过 SSE 轮询等待（最长 120 秒）
    ↓
超时或完成后显示内容
```

**问题**:
- 并行调用总耗时长（2-5 分钟），容易超过 120 秒超时限制
- 全部完成后才推送，用户长时间无反馈
- 内存缓存重启后数据丢失

### 2.2 优化后流程（V1.1）

```
用户提交主题
    ↓
Step 1: 生成全景介绍（30-60秒）
    ├─ 调用 LLM 生成全景介绍
    ├─ 完成后立即缓存（文件缓存 + 内存缓存）
    └─ SSE 推送 stage: "overview_done"
    ↓
Step 2: 生成知识结构（60-180秒）
    ├─ 调用 LLM 生成知识拆分
    ├─ 解析 JSON → 生成 UUID → 缓存
    └─ SSE 推送 stage: "completed"
    ↓
持久化到本地文件（topic_name 为 key）
```

### 2.3 SSE 流式推送增强

**原设计**: 仅支持 `completed` / `timeout` 两种状态

**改进后**: 支持三阶段状态推送

| stage | 含义 | 前端行为 |
|-------|------|----------|
| `processing` | 正在生成全景介绍 | 显示"AI正在分析主题..." |
| `overview_done` | 全景介绍已可用 | 先显示全景介绍，继续等待知识结构 |
| `completed` | 全部完成 | 显示完整知识体系和全景介绍 |
| `timeout` | 300秒超时 | 检查本地缓存，有数据则显示，否则提示刷新 |

**超时时间**: 从 120 秒延长至 300 秒

### 2.4 错误容错机制

**新增 fallback 策略**:

| 步骤 | 失败场景 | fallback 行为 |
|------|----------|---------------|
| 全景介绍生成 | LLM 调用失败 | 使用默认文本 `"## {主题名}\n\n正在准备学习内容..."` |
| 知识结构生成 | LLM 调用失败 / JSON 解析失败 | 使用默认知识结构（2个知识块、4个知识点） |
| 文件持久化 | 磁盘写入失败 | 仅使用内存缓存，不影响前端展示 |

## 三、技术实现细节

### 3.1 关键文件变更

| 文件 | 变更类型 | 说明 |
|------|----------|------|
| `backend/app/db/database.py` | 修改 | 添加 PostgreSQL 检测和 SQLite fallback |
| `backend/app/api/v1/endpoints/topics.py` | 修改 | 重构 `_process_topic_background`，新增 `_get_default_structure` |
| `frontend/src/App.tsx` | 修改 | 增强 SSE `onmessage` 处理，支持 `overview_done` |

### 3.2 数据库连接配置示例

**SQLite 模式（默认）**:
```python
# 无需配置，自动使用
DATABASE_URL = "sqlite:///ai_education.db"
```

**PostgreSQL 模式**:
```python
DATABASE_URL = "postgresql://edu_user:edu123456@127.0.0.1:5432/education"
```

### 3.3 知识体系生成耗时参考

| 阶段 | 预计耗时 | 累计耗时 |
|------|----------|----------|
| 全景介绍生成 | 30-60 秒 | 30-60 秒 |
| 知识结构生成 | 60-180 秒 | 90-240 秒 |
| 总计 | - | 90-240 秒 |

**优化效果**:
- 用户可在 30-60 秒内看到全景介绍（而非等待 2-3 分钟）
- 超时误判率降低（300 秒超时覆盖 95% 场景）
- 失败时有默认内容，避免页面空白

## 四、后续优化建议

1. **预置热门主题缓存**: 对"Python编程"、"数据分析"等热门主题预置完整 mock 数据，实现秒开

3. **增量更新**: 知识结构支持增量更新，避免全量重新生成
4. **多模型负载均衡**: LLM 调用支持多 Provider 轮询，提升可用性
